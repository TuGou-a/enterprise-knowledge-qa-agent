# 阶段复盘

本文复盘 T09 的准备阶段，不代表项目已经运行验收。实际投入时间未统计，个人学习感受与线下排查经历待用户补充。

## 当前难点与处理

本轮最需要厘清的是「测试代码已经编写」能证明什么。任务基线只有 T01 的配置与契约，问答、检索、原文读取和校验器仍没有实现；如果另写一套固定问答逻辑再测试它，只能证明那套替身自身符合预期，无法验证实际业务服务。

因此先测试真实存在的边界约束，并明确将完整 Mock 循环、实际检索和真实模型路径留待业务实现合并后补齐。测试入口不扫描完整应用；原先空的 `contextLoads` 需要真实配置和数据源，不适合作为无业务密钥的离线基线。新的隔离配置绑定测试与纯契约测试已经编写，效果仍待实际执行。

另一处取舍是区分「引用确实存在」与「引用支持答案」。向量合法性、JSON 枚举和读取结果互斥可由确定性测试检查；答案是否遗漏条件、如何解释 30 天/15 天冲突，以及模型是否观察工具结果后改变动作，需要实际 Trace 和人工核对。相应术语、指标与阻断缺陷已写入 [评估文档](03-evaluation.md) 和 [术语表](../GLOSSARY.md)。

## 当前能确认的收获

- 契约测试与业务验收的边界已明确，未实现的模块没有用空测试计为通过。
- 二元相关条款标注、主候选与主题扩展的统计口径已确定，检索指标不替代答案支持性判断。
- 计划输入、Mock 结果、真实运行与真实系统加故障注入分别说明来源，避免示例材料冒充实际证据。

这些是本轮已形成的设计和材料，不是运行效果结论。

## 尚未验证的风险

AgentScope 2.0.4 与现有 Spring Boot 的依赖兼容性、PostgreSQL 查询与快照行为、实际工具循环、取消阻塞调用的效果，以及云模型可用性仍待后续测试。契约测试只能覆盖有限边界；首次编译和执行也可能暴露测试代码或依赖问题，需要按实际错误修复。

## 下一步

1. 本轮由子代理静态审查、主代理修复后合并到 `dev`，删除任务 Worktree；等待用户测试指令。
2. 随业务模块合并补齐对应实现测试，固定真实资料并完成条款标注。
3. 获准验证后，记录编译、离线测试、真实数据库、模型决策、故障和文档替换的实际结果。
4. 完成四种检索方案对比，保留失败和未提升的结果，再依据证据决定是否调整。
5. 补充个人实际投入、亲自修改与独立学习经历，并形成最终复盘。
