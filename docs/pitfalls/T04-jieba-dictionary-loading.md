# T04：jieba 自定义词典加载不会向调用方传播 I/O 失败

## 现象

`WordDictionary.loadUserDict(Path, Charset)` 返回 `void`。静态读取已缓存依赖的字节码发现，它捕获 `IOException` 后只向标准错误打印提示，调用方无法仅靠方法正常返回判断词典已加载。

## 环境

项目声明 Java 17、Spring Boot 3.5.10 及 `com.huaban:jieba-analysis:1.0.2`。本结论来自本机该版本 JAR 的 `javap -c -p` 静态读取，未启动应用、调用分词器或构造实际失败，因此运行现象仍待授权验证。

## 原因

库将词典读取错误留在内部，且只加载满足其行格式的条目。它使用进程共享的 `WordDictionary`；调用方也不能把每次请求都重新加载资源当成版本隔离。只传路径并继续发布资料，会使声明的词典配置与实际索引行为不符。

## 解决方案

T04 在启动边界严格读取 UTF-8 资源，检查有效条目、词频和重复词；把规范化后的完整内容写入临时文件再交给库加载，并检查实际词典包含目标词语且对应频率为有限数值。临时文件在加载结束后删除，资源读取或清理失败均明确报告。

该核对用于发现未加载的新词和无效频率，不宣称可以证明库对已有词的每次频率更新都成功。输入文件经本地读取固定后，加载的是同一份已校验内容；首版不新增反射访问、热加载或多个运行期词典实例。

词典和停用词配置在进程启动时固定，资源变化须更新版本、重启并重新导入快照。未来若要求同一进程承载不同词典或热更新，应重新评估当前库的共享状态，不能直接复用此实现宣称已隔离。
