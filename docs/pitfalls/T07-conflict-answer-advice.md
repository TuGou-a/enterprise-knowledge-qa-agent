# T07：冲突状态与回答正文不一致

## 现象

E02 的历史运行 `ea61d620-9563-4a43-b3e7-e481eca8f6f1` 返回 `CONFLICT/APPLICABILITY_UNKNOWN`，引用 D01 的 30 个自然日和 D02 的 15 个自然日规定，但正文仍包含：

> 在冲突未消解前，为避免超期，建议按较严格的 15 个自然日时限把握，但这只是风险提示，不构成制度结论。

这段建议实际替用户选择了 15 天规定，违反冲突未消解时请求确认适用制度的要求。正文还声称差旅制度没有报销提交期限，而同次 Trace 只记录了 D01、D02 的读取；候选预览不足以支持对另一份制度的否定结论。

原始材料见[回答](../../examples/real/E02/ea61d620-9563-4a43-b3e7-e481eca8f6f1/response.json)与 [Trace](../../examples/real/E02/ea61d620-9563-4a43-b3e7-e481eca8f6f1/trace.json)。这些文件保留原样，不能作为修复后的证据。

## 环境

- 历史运行：macOS、Java 21.0.12、Spring Boot 3.5.10、AgentScope Java 2.0.4、DeepSeek `deepseek-chat`。
- 资料：`conflict` 快照，D01、D02 未说明适用范围、优先级或替代关系。
- 运行时：结构化草稿经过状态、引用与已观察证据校验。

## 原因

提示词禁止自行选取规定，但未明确覆盖「风险提示」「较严格」「暂按执行」等变相建议。机械校验器只验证结构、引用及状态最低前提，会原样透传模型生成的正文、缺口和追问；引用真实不代表其余正文均受支持。

真实问答评估入口保存了请求、响应和 Trace，但没有对 E02 的冲突状态、双方引用或补查路径设置硬断言。执行成功和状态正确因此被误认为冲突处理符合要求。

## 解决方案

1. 提示词明确禁止冲突未消解时推荐任一方，包括以风险提示或较严格期限为由的建议；禁止根据预览或局部原文推断整份制度没有某项规定，并要求冲突引用保留完整条款和条件。
2. 在现有输出边界统一展示合法 `CONFLICT`：只并列核验引用，说明不能选取任一方执行，并要求制度归口部门确认适用关系。正文、缺口和追问均不透传模型自由文本，避免建议通过其他字段返回。
3. 保留原有非法结构、非法引用整体拒绝与失败优先级。冲突在路由、读取或主题完整性受限时仍追加真实限制；预算耗尽等高优先级终止仍返回 `INCOMPLETE`。
4. 补充校验器回归及实际服务的恶意草稿场景；真实 E02 在保存实际证据后检查状态、双方完整引用、补查与读取后的模型观察。机械断言不能代替完整语义复核。
5. 更正评估文档中该次 E02 的通过表述，不修改历史回答，不补造修复后的运行结果。

冲突识别与工具选择仍由模型完成；统一展示不证明两条原文在语义上冲突，也不引入自动修复模型调用。
