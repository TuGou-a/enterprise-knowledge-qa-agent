# T09 评估资料身份不能只用正文哈希

## 现象

静态审查发现，真实问答评估若只核对快照 ID 和集合 `contentHash`，可能把适用范围、替代关系、主题或片段偏移不同的快照当作同一参考资料。这会影响冲突识别、主题扩展和引用定位。当前未运行复现。

## 环境

T04 每次导入生成随机快照 UUID；集合哈希由排序后的文档 ID、版本和正文哈希计算。T09 同时提供参考标注、真实检索评估和真实问答采集。

## 原因

正文哈希标识正文，不包含适用范围、替代关系、主题和切分结果。源 JSON 文件摘要能确认本地输入未改变，却不能单独证明数据库内的元数据和片段与该输入一致。

## 解决方案

参考标注固定源文件 SHA-256 和集合哈希，运行时绑定实际 READY 快照。两个真实评估入口共用测试侧 `CorpusEvaluationBinding`：核对索引配置，重新解析源资料，逐条读取并比较 `KnowledgeChunk` 和 `DocumentMetadata`。不修改生产持久化协议或哈希算法。
