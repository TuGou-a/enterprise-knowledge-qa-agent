# 按固定快照和相同查询判定召回恢复

用户于 2026-10-31 确认：同一请求中的召回失败不能被任意一次后续成功覆盖。首版仅在固定快照内，相同查询的对应失败路由成功补查且查证限制补足时清除错误；查询只去除首尾空白，不认定改写查询语义等价。原始错误继续保留在 Trace。

让模型声明「已经恢复」或按最近一次成功覆盖运行状态，实现更宽松，但不能保证原查询的资料范围得到补足。本方案便于由应用检查，并避免无关检索清除失败；代价是部分改写后实际上已经找到充分资料的请求仍保守地返回 `INCOMPLETE`。该约定同时影响 T05 检索结果、T07 运行聚合及 T06 完成校验，调整时须共同修改契约与验收用例。
