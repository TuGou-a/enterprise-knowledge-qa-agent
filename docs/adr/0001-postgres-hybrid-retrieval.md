# 使用 PostgreSQL 与 pgvector 承载混合检索

本项目需要在有限开发时间内完成报销与差旅制度问答，并覆盖相似改写和文档冲突。根据用户选择，采用一个 PostgreSQL 数据库保存版本化原文、关键词索引和 pgvector 向量，降低部署组件与索引同步的复杂度；关键词路由使用 Java jieba 分词后交给 PostgreSQL 全文检索，向量由硅基流动 `BAAI/bge-m3` 生成。

相比独立检索引擎与向量数据库的组合，本方案需要自行实现 SQL 查询、结果融合和版本一致性。初期采用向量精确检索、全文索引与 RRF；按用户后续选择，通过 MyBatis Mapper 管理 SQL，融合候选后调用硅基流动 `BAAI/bge-reranker-v2-m3` 重排序。重排序失败回退 RRF，同主题版本单独扩展，排序不能决定制度适用性。参数与效果以实际评估结果为依据。

该决策确定数据与索引的归属，后续替换数据库需要迁移原文、版本关系及两路索引；更换重排序模型只影响查询时排序，不需要因此重建文档向量。
