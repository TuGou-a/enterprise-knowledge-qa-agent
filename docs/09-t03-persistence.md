## 实现内容

- `PgKnowledgeStore` 实现全部 11 个持久化方法。`KnowledgeMapper` 使用 `@Mapper` 注册，XML 路径沿用 T01，无需修改启动类或共享配置。
- 三表保存完整索引配置、文档元数据与原文、片段与两路索引。`supersedes` 通过专用 JSON TypeHandler 映射，不注册全局 List 处理器。
- 文档和片段每批使用独立短事务，先锁定并检查 `BUILDING` 快照。发布事务复用同一快照锁，防止发布与批次写入交错。
- 发布时以数据库中的文档键和内容哈希重新计算集合哈希，核对清单的文档数、片段数及集合哈希后更新 `READY` 和数据库发布时间。
- 向量查询采用余弦距离升序，关键词查询采用 `ts_rank_cd` 降序；两路先按完整稳定键打破并列，再执行 LIMIT。返回 rank 从 1 开始，rawScore 保留各路原始量纲。
- 关键词词元为空时只校验参数，不获取数据库连接；正值的亚秒超时也正常返回空。读取未发布快照时抛出快照不可用，不将其误报为片段不存在。
- 主题扩展按主题及稳定键排序，排除调用方指定的主候选，读取 `limit + 1` 条判断截断；上限为 0 时仍可探测是否存在未展示资料。
- 批量原文读取按请求键重新排列。缺少任一键时整批失败；不会登记已读证据。单片段读取同时返回文档元数据与原文偏移、哈希。
- 预览按 UTF-16 字符上限生成，保留完整原文，并避免在代理项中间截断预览。

## 错误与超时交接

| 情况 | Failure.code | retryable |
| --- | --- | --- |
| 无可写的指定快照 | `SNAPSHOT_UNAVAILABLE` | false |
| 重复主键、约束失败、跨快照批次或键、重复发布、清单不符 | `INVALID_ARGUMENT` | false |
| 批量读取缺少任一片段 | `NOT_FOUND` | false |
| 语句或事务超时 | `TIMEOUT` | true |
| 连接不可用、暂时性数据库资源故障 | `DATABASE_UNAVAILABLE` | true |
| 数据库认证失败 | `AUTHENTICATION_FAILED` | false |
| 数据库返回的字段或 JSON 无法映射 | `INVALID_RESPONSE` | false |
| 剩余预算不足一秒 | `BUDGET_EXHAUSTED` | false |
| 其他未归类的 SQL 或事务错误 | `INTERNAL_ERROR` | false |

`retryable` 描述错误性质，本实现不自动重试；导入的恢复方式仍为新快照完整重导。错误消息使用固定文案，不向调用方返回 SQL、连接信息或数据库原始错误体。

数据库调用先检查正超时，再在短事务中按获取连接后的剩余预算收紧截止时间。MyBatis 拦截器在每条新语句前向下换算整秒，少于一秒时拒绝查询。连接获取仍受 T01 全局连接池等待上限约束，不能承诺底层阻塞在更短的调用方预算到期时立即结束；详情见 [T03 超时踩坑](pitfalls/T03-transaction-timeout-budget.md)。
