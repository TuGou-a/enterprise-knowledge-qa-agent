# 企业知识问答 Agent：需求基线

本文依据[题目要求](./题目要求.md)和当前会话记录整理。状态为需求讨论稿；尚未确定的设计选项不作为已确认需求。

## 已确认的目标与约束

- 服务员工，回答制度或产品问题，并提供可核对的依据。
- 输入包含问题和可选对话历史；知识材料使用带文档 ID、版本日期的合成 FAQ 或制度。
- 提供文档检索工具与原文片段读取工具。
- 输出包含回答、引用文档 ID、原文片段、资料缺口和任务状态。
- 使用 Maven 依赖 AgentScope Java。此项来自用户要求。
- 最终架构设计以 HTML 文档交付，结合架构图、流程图与文字说明。此项来自用户要求。
- 当前阶段讨论需求与架构；开发业务功能不属于本阶段的交付。

题目建议投入 3 天，允许以 CLI、HTTP API 或 Notebook 作为运行入口；界面、线上部署、多 Agent 和生产级 Runtime 均非必需。用户已选择先完成考核要求、沿用现有 Spring Boot 后端，以 HTTP API 为主要入口。实际用时在后续实施中如实记录。

## 必须可观察的 Agent 决策

至少实现一次「模型选择动作 → 执行工具 → 观察结果 → 模型调整动作或结束」循环。允许预设执行骨架，但固定条件分支、自动重试或预设决策日志均不能代替真实模型决策。

模型应能根据材料选择补充检索、读取原文、追问或停止。发生文档冲突时，必须说明冲突并查证；资料不足以确定适用范围或优先级时，不能自行选择一条规定。

必须设置执行步数或工具调用次数上限。到达上限时返回明确的未完成状态。

## 验收点与验证方向

下表中的验证方向是测试设计依据，不代表已有测试通过。

| 编号 | 题目验收点 | 应验证的行为 |
| --- | --- | --- |
| R01 | 明确答案 | 从合成文档检索并读取依据，回答与引用原文一致。 |
| R02 | 文档冲突 | 同一问题出现「30 天」与「15 天」，缺少适用范围或优先级时展示双方依据并请求确认。 |
| R03 | 资料外问题 | 说明现有资料不能支持回答，并指出资料缺口，不以模型常识替代文档依据。 |
| R04 | 改写后的相似问题 | 问法变化后，仍能找到与原问题相同或等价的支持材料。 |
| R05 | 上下文追问 | 利用前序对话理解省略对象的追问，并重新核对相应依据。 |
| R06 | 工具失败 | 记录真实失败，观察模型如何调整动作；无法继续时明确说明限制。 |
| R07 | 动态动作调整 | 至少两条实际运行路径体现模型根据不同工具结果改变后续动作。 |
| R08 | 执行上限 | 达到执行步数或工具调用次数上限时，以明确的未完成状态结束。 |
| R09 | 文档内容替换 | 替换资料后重新运行，核对回答与动作是否随依据变化。 |
| R10 | 离线入口 | 无模型服务时可运行 Mock，明确其只能验证流程，不能证明真实模型决策效果。 |

## 验证与提交材料

至少提供 3 组输入、实际输出和运行记录，覆盖正常、信息或资料不足、工具失败场景，同时覆盖全部验收点。同一用例可以覆盖多个验收点。

运行记录包含步骤、工具参数、返回摘要、后续动作与简要决策依据；不要求模型内部思维过程。Trace 与测试结果放在 `examples/`，评估文档引用对应文件。

代码仓库还需包含可执行测试、合成资料、依赖文件、`.env.example`，以及下列文档：

- `README.md`：环境、安装、可复制的运行步骤与评审入口。
- `docs/01-requirements.md`：用户、目标、范围与成功标准。
- `docs/02-solution.md`：调用流程、动态决策与技术取舍。
- `docs/03-evaluation.md`：测试预期、实际结果、失败与限制。
- `docs/04-ai-usage.md`：AI 辅助范围、个人贡献和验证结果。
- `docs/05-retrospective.md`：最难问题、学习收获和下一步。

使用框架时，注明版本、使用的功能和承担的职责。最终提交题号、GitHub URL 和 commit SHA；不得提交真实密钥或隐私数据。

HTML 架构文档用于说明设计，不能代替运行代码、实际 Trace、测试结果与其他题目要求的材料。
