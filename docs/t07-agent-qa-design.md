# T07 Agent 与问答服务

本文记录 T07 的设计与交接。用户于 2026-11-01 确认两项开放决策及整体方案，并授权开始实现。生产代码已实现，正在进行子代理静态审查；尚未执行编译、启动、依赖树、测试或模型请求。开发基线为 `dev` 的 `052bffb`，任务分支为 `task/t07-agent-qa`，独立 worktree 为 `/private/tmp/agent-t07-agent-qa`。

## 目标与已有约束

按[开发计划](06-parallel-development-plan.md)，T07 实现 `qa/agent/**`、`qa/application/**`，为已有 HTTP 入口提供可被 Spring 发现的 `QaService` 实现。接入 T05 的检索和原文读取、T06 的输出校验和 Trace 工厂，实现真实模型根据工具观察选择下一步的问答循环。

以下内容已有定稿，本轮沿用，不作为新决定：

- 每次订阅创建独立运行，固定最新 READY 资料快照并核对索引配置；运行前快照不可用或配置不匹配交由既有 HTTP 错误边界处理。
- 使用 AgentScope Java `2.0.4` 和 DeepSeek Provider，显式关闭思考模式；工具顺序执行，模型与工具均不自动重试。
- 仅暴露 `searchKnowledge`、`readKnowledge` 两个业务工具；通过框架运行上下文注入快照、预算、证据和检索聚合状态，模型不能自行指定这些字段。
- 历史保留原始顺序和内容，只用于理解追问，不作为制度依据；不保存跨请求会话。
- 分别限制 ReAct 轮次、获准执行的业务工具数、总截止时间、累计原文与工具文本字符，以及每次完整模型输入。框架内部的结构化输出工具不计入业务工具次数。
- 引用只接受本次固定快照中已读的原文；草稿交由 T06 校验，应用填充真实运行字段。多原因优先级、同查询恢复、冲突例外及无依据状态的最低前提沿用既有契约。
- T06 提供请求独立的内存 Trace；T07 负责实际事件采集与最终结果接线，真实 Trace 文件和评估示例由 T09 负责。

依据：[T01 契约](08-t01-contracts.md)、[T05 设计](t05-search-design.md)、[T06 交接](09-t06-output-validation-trace.md)、[T08 设计](t08-http-design.md)、[查询恢复决定](adr/0002-query-scoped-recovery.md)和[HTTP 失败边界](adr/0004-http-failure-boundary.md)。业务术语沿用根目录 [GLOSSARY.md](../GLOSSARY.md)。

## 本轮静态核查

本地参考仓库的 `v2.0.4` 中，`ReActAgent.dispatchToolCalls` 在同一轮同时包含普通工具与 `generate_response` 时，先执行普通工具，再执行本轮已经生成参数的结构化工具。因此，「读取先执行」不能证明模型已经观察读取结果；即使引用能通过已读证据检查，也可能引用本轮刚读到、生成草稿时尚未观察的内容。

现有[框架接入核查](framework-verification.md)和 T01 已要求后续真实 Trace 证明读取完成后还有模型推理，但没有明确这一要求在 T07 中的运行时处置方式。

以上是对目标发行版源码的只读核查，未执行编译、启动、依赖树、测试或模型请求。

## 已确认决策

### Q1：最终草稿必须基于生成前已观察的引用证据

用户于 2026-11-01 确认在 T07 增加运行时检查：最终草稿引用的每个片段，必须在生成该草稿的模型调用开始前，已有成功读取并交付给模型的记录。若草稿使用同轮才读取的片段，按无效输出处理，返回 `INCOMPLETE/OUTPUT_INVALID`，不展示未经观察确认的答案，也不追加自动修复调用；更高优先级的实际运行限制仍优先。

这一检查关注引用证据与模型调用的先后关系；它不证明答案语义受证据支持。若引用所需原文在更早轮次已经读过，同轮再次读取该片段不应使草稿失效。

状态：已确认。未采用仅依靠提示词和后续 Trace 验收的方案。

`OUTPUT_INVALID` 在这里标识草稿违反证据观察顺序；片段存在且原文一致，并不能消除这一问题。片段不存在、版本或引用原文不匹配等引用本身无效的情况，继续交由 T06 判为 `CITATION_INVALID`，不改变既有规则。

### Q2：业务工具必须提供公开用途

用户于 2026-11-01 确认将两个业务工具的 `purpose` 设为必填的简短说明，并写入 Trace 的 `publicPurpose`。说明只描述查询或读取的目的，不要求内部思维过程。模型遗漏时返回参数错误观察，允许在现有轮次和时间预算内重新选择动作，不替模型编造决策依据。

状态：已确认。该决定收紧原工具设计中用途说明可选的约定，不改变跨任务工具服务接口。

## 实施方案

### 请求生命周期

`QaService.answer` 使用延迟创建的响应式链：每次订阅生成独立运行 ID、预算与记录器，在线程适合执行阻塞数据库操作的边界选择 READY 快照并核对索引配置，再创建 `RunContext` 和本次 Agent。快照选择不随工具调用变化，不在单例服务中保存当前请求。

运行前无法建立可靠上下文时，保留既有依赖异常与 HTTP 映射。运行建立后，已知模型失败、总超时和执行限制由应用形成可解释的任务结果；未预期的内部故障继续交由既有系统错误边界处理，不将所有异常吞并为任务结果。

### 请求级状态

在 `qa/application/` 实现 `ExecutionBudget`、`EvidenceRegistry`、`RetrievalLedger`，分别负责单调时钟与原子预占、当前快照的已读原文，以及按查询范围和片段键管理限制与恢复。聚合规则逐项遵循 T01，不用最近一次成功覆盖整个运行状态。

证据登记与模型观察分开：成功读取的原文进入已读证据；在实际模型调用边界确认其已进入本轮输入后，才能作为该轮草稿的已观察证据。T06 继续负责引用存在性和原文一致性，T07 额外落实 Q1 的观察先后约束。

### 工具与框架接入

在 `qa/agent/` 组装 DeepSeek 模型、请求独立的 ReAct Agent、顺序 Toolkit 和中间件。历史按调用方原始角色、顺序与内容进入本次对话，当前问题追加在历史之后。

工具包装层校验模型可填参数，包括 Q2 已确认的必填公开用途，记录请求值与实际值，预占业务调用次数，并调用 T05。搜索成功后预占实际预览字符；预览无法交付时保留真实检索结果与同一条完成事件中的交付错误。读取预算与证据登记继续由 T05 承担，不重复扣减。工具错误作为明确观察返回，保持真实错误与空结果的区别。

中间件在实际模型调用前检查完整输入和剩余时间，限制单次模型调用；总截止时间覆盖整个结构化调用，包括框架的追加汇总。记录真实模型阶段、业务工具开始及唯一完成事件、轮次上限和最终状态，不记录模型内部思维过程或原始外部错误体。

提示词明确要求：先读取再引用；冲突时阅读双方并补查适用关系；日期和排名不代表制度优先级；资料不足时说明缺口；工具失败后根据观察决定是否补查。上述业务判断由模型完成，不在应用中预写「30 天／15 天」等固定决策路径。

### 最终结果与交接

先判实际超时、预算、上限及模型失败，再处理结构化草稿、Q1 观察约束与 T06 校验，按既定优先级组装结果。模型不填写运行 ID、快照、预算或检索摘要；最终 Trace 引用集合与实际返回的一致。

本次交付新增生产实现与必要设计、踩坑文档，不增加聊天界面、服务端会话、Trace 查询接口或持久化层。测试和真实评估材料继续按 T09 分工补齐；本次静态交接列明待验证项，不预填通过结果。

## 实现入口与待验证项

- `qa/application/AgentQaService`：每次订阅独立建运行、选择并校验快照、传入原始历史、调用 Agent、处理已知失败及组装最终结果。
- `qa/application/RequestExecutionBudget`、`RequestEvidenceRegistry`、`RequestRetrievalLedger`：提供 T05、T06 所依赖的三项请求级状态实现。
- `qa/agent/QaAgentFactory`：通过 Spring 创建无请求状态的模型客户端，每次运行创建独立 Agent、Toolkit 与中间件；测试可替换现有 `Model` Bean，不新增 Mock HTTP 入口。
- `qa/agent/KnowledgeTools`：注解工具注册、公开用途与参数校验、业务调用许可、预览交付预算和结构化观察。`purpose` 去除首尾空白后必须为 1 至 200 个 UTF-16 字符。缺少必填字段时框架拒绝调用，T07 仍记录一次参数错误观察，不消耗业务执行许可。
- `qa/agent/QaAgentMiddleware`、`AgentRunState`：限制单次模型调用和完整输入，关联实际调用标识与交付事件，核对生成前已观察证据，并封存结束或取消前的事件。工具装饰器向运行上下文注入 `ToolCallParam`，使注解方法能读取框架真实 callId，不使用共享当前请求字段或 ThreadLocal。

完整输入按系统提示词、历史、观察、工具定义和输出 schema 的序列化表示检查字符上限，并用 UTF-8 字节数为文本 token 使用量提供保守上界，预留配置的输出 token 数。这是应用侧的保守检查，不是服务商 tokenizer 的精确计数，也不证明真实模型窗口与配置完全一致；它可能提前拒绝实际能够容纳的输入，须在后续真实调用中评估。

`reactIterations` 记录实际开始的模型调用，包括达到 ReAct 上限后框架实际发起的汇总调用；因此可能大于 `maxReactIterations`。是否达到轮次上限取独立标志，不按两个数的大小猜测。汇总仍受完整输入、单次模型和请求总预算约束，不能把汇总文本当作成功答案。

后续待授权验证：Java 17 编译与 Spring 启动、Boot 管理依赖与 AgentScope 2.0.4 兼容性、工具参数注入和顺序执行、全部状态及失败优先级、相同查询恢复与截断、同轮新增引用拒绝、读取交付事件、流式调用总超时、取消后的事件封存，以及真实模型的正常、冲突、追问和故障路径。本轮静态审查不能替代这些运行证据。
